# Chess-playing-robot

## Шахматная сессия

Для установки зависимостей в существующее виртуальное окружение:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Пример использования:

```python
from src.chess_core.game import ChessGame

game = ChessGame()
game.push("e2e4")
print(game.board)
print(game.outcome)  # None, пока партия продолжается
```

Возможны загрузка позиции через `ChessGame(fen)`, отмена через `undo()` и сдача через `resign()`. Автоматические окончания партии определяются python-chess; заявление ничьей по требованию пока не реализовано.

## Stockfish

Установите Stockfish с [официальной страницы](https://stockfishchess.org/download/). Скопируйте `config/engine.example.toml` в `config/engine.local.toml` и укажите в нём путь к исполняемому файлу (в TOML можно использовать прямые слеши, например `C:/Stockfish/stockfish.exe`). Настройки `time` и `timeout` задаются в секундах, `depth` необязательна.

```powershell
.\.venv\Scripts\python.exe -m src.chess_core.engine_cli --config config/engine.local.toml
```

Для другой позиции добавьте `--fen "<FEN>"`. Движок скачивается отдельно и не хранится в репозитории.

## Определение хода и виртуальная рука

`src.chess_core.move_detector.detect_move(board, before, after)` принимает два `BoardObservation` и возвращает статус, ход и кандидатов. Оба наблюдения должны быть стабильными и содержать 64 клетки. Порог уверенности настраивается. В режиме `require_changes=True`, который использует контроллер, набор `after.changed_squares` должен включать все клетки, где изменилась фигура. Пустой набор означает, что изменений не обнаружено. Отдельный вызов детектора без этого режима поддерживает синтетические наблюдения, построенные только по занятости. Неоднозначное превращение не выбирается автоматически.

`src.robot.move_planner.plan_move` строит логические действия для легального хода. Для каждой убираемой фигуры передаются отдельные свободные идентификаторы `capture_slots`; для превращения также нужен словарь `reserve` из идентификаторов слотов и фигур `chess.Piece`. Проверка фактической доступности слотов при исполнении остаётся за рукой. Планировщик поддерживает обычные шахматы, но не Chess960.

`src.robot.mock_arm.MockArm` принимает начальную `chess.Board` и запас фигур, исполняет отдельные действия и ведёт `pieces`, `captured`, `reserve` и `log`. Отказы можно воспроизвести через `fail_next`, аварийную остановку сбросить через `reset_stop`. После ошибки уже выполненные действия остаются в силе.

## Контроллер партии

`GameController(game, vision, engine, arm)` связывает шахматную сессию, зрение, движок и руку. По умолчанию робот играет чёрными. Для взятий передайте свободные `capture_slots`, для превращений также передайте `reserve`. Начальное состояние резерва должно совпадать с резервом руки.

На выпрямленной доске `a1` находится слева внизу при любом цвете робота. Порядок углов при калибровке — `a1 → h1 → h8 → a8`. Контроллер использует три метода зрения:

- `get_initial_observation(timeout=...)` получает первый свежий стабильный кадр без эталона. Контроллер сверяет занятость 64 клеток с начальной позицией партии.
- `get_observation(timeout=...)` ждёт свежие кадры без перекрытия рукой, оценивает стабильность и сравнивает итоговый кадр с последним эталоном. До установки эталона этот метод должен сообщать о неготовности. После хода робота вызов происходит после остановки руки. По истечении времени ожидания зрение поднимает `TimeoutError`.
- `confirm_observation(observation)` сохраняет точный кадр, соответствующий наблюдению. Контроллер вызывает метод после сверки начальной позиции и после каждого подтверждённого хода. При взятии в `changed_squares` включается и занятая целевая клетка.

`observation_timeout` по умолчанию равен 10 секундам на запрос. `min_confidence` по умолчанию равен 0,9 для каждой клетки. Это предварительный порог оценки качества, который предстоит подобрать по реальным кадрам. При превращении камера сверяет занятость клетки, а контроллер полагается на отчёт руки об установке выбранной фигуры.

При сбое руки или подтверждённом расхождении контроллер останавливается в `ERROR`, причина доступна в `controller.error`. Для продолжения сначала восстановите или согласуйте расстановку и слоты с шахматной сессией, затем создайте новый контроллер.

```powershell
.\.venv\Scripts\python.exe -m pytest -q tests/test_game_controller.py
```
